# 江月UI设计 · 视频制作

这个系列每期 12 秒：一张 6 宫格画面，每格是一个 UI 效果的实时动画，配英文术语和中文名，标题是「给 AI 描述 **XX**，记住这 6 个词」。同一份素材产出 4 样东西：横屏视频、竖屏视频、两张封面、两份发布文案。然后接入开源网站「UI 提示词图鉴」。

**风格是系列的生命**。优化可以做在流程、质量和效率上，画面长相和文案口吻必须与已发布的期数保持一致。做之前先读：
- `references/视觉与动效规范.md`：画布、宫格、配色、4 秒节拍、封面帧
- `references/文案规范.md`：标题、正文 6 行、Prompt、置顶评论的写法
- `references/期数台账.md`：已发布哪些期、下一期预告了什么、选题池

参考成品：仓库根目录的 `EP11 按钮点击反馈/` 是最新、最规范的一期，写新镜头时可以直接对照它的写法。

## 目录约定

```
EPxx 主题/                      ← 仓库根目录下，每期一个文件夹（主题用中文全称）
  主题 动画网页.html
  主题 发布文案.md
  主题 抖音发布包.md
  主题（横屏 16比10）.mp4        ← render.mjs 生成
  主题（竖屏 9比16）.mp4
  主题 封面（横屏）.png
  主题 封面（竖屏）.png
图鉴网站（开源）/episodes.json    ← 网站的期数登记表；网站直接读上面的动画网页和发布文案，不另存副本
```

下文 `$SKILL` 指本 skill 所在目录 `.claude/skills/jiangyue-ui-video`。

## 流程

### 1. 自动定选题和 6 个词（不用等用户确认，直接往下做）
- 查 `期数台账.md`：上一期置顶评论预告过的主题必须先做；没有预告时，从选题池里挑观众搜索热度最高、和已发布期数不重复的主题。确定系列第 N 期，EP 编号取已用编号的最大值 + 1。
- 选 6 个词：英文术语 + 中文名（≤7 字）+ 一句话说明它在宫格里怎么演。选词标准：观众每天在 App 里见过、却叫不出名字；在 456×224 的宫格里 4 秒内演得清楚；6 个词彼此差异明显，避免两个词演出来差不多（例如 Spring 和 Overshoot 只留一个）。
- 预告里点名过的词必须包含在内。
- 用户指定了主题或词，就按用户的来。

### 2. 写动画网页
- 复制 `$SKILL/templates/动画网页.html` 到 `EPxx 主题/主题 动画网页.html`。**外壳段落一个字都不改。**
- 改 `<title>`、标题 `<em>` 里的关键词（2–8 字），写 6 个 `.cell`。
- 每个镜头：一个 2 字母 class 前缀；一个语义色相 `hue-xxx`；骨架上下文 + 唯一上色的主角；所有 keyframes 挂 `var(--clock)`；遵守 0–15–25–65–100% 节拍；**2.4s 那一刻停在结果状态**。
- 竖屏不用另写，外壳会按 `#portrait` 自动重排。
- `term-en` 里的 `&` 直接写 `&`，不要写 `&amp;`，否则文案和网站对不上术语（check.mjs 会报）。
- 抽象概念（缓动、节奏这类）要配“对照物”或“痕迹”，让静止的封面也看得懂：例如灰色匀速小球作对照、等时间间隔的采样点、虚线标出冲过头的位置、虚线画出运动路径。

### 3. 先看封面帧，再录视频
```bash
node $SKILL/scripts/render.mjs "EPxx 主题/主题 动画网页.html" --cover-only
```
用 Read 打开两张封面逐格检查：每格是否一眼能看出是哪个词，有没有元素被裁，颜色是否重复。有问题回第 2 步改。必要时用 `--cover-at 1.2` 这类参数看其他时间点的画面，检查动作中途的状态。

### 4. 写两份文案
复制 `$SKILL/templates/发布文案.md` 和 `抖音发布包.md` 并填写，规则见 `文案规范.md`。重点：
- 正文 6 行严格使用 `1️⃣ English Term，大白话，比如场景` 格式，顺序与宫格一致
- 每段 Prompt 都带英文术语本身和具体数值
- 置顶评论里的“下一期”与台账一致。如果下一期还没定，先从选题池挑一个，请用户拍板

### 5. 自检
```bash
node $SKILL/scripts/check.mjs "EPxx 主题"
```
有 ✗ 必须修；⚠ 逐条判断。

### 6. 渲染成片
```bash
node $SKILL/scripts/render.mjs "EPxx 主题/主题 动画网页.html"
```
输出横屏 1920×1200、竖屏 1080×1920，均为 60fps、12 秒（4 秒 × 3 圈），以及两张封面。逐帧精确渲染，不丢帧，约 3 分钟。渲染完用 ffprobe 确认 720 帧、12 秒，再抽 1–2 帧看一眼。
- 依赖：Node 18+、`playwright`（含 Chromium）、`ffmpeg`
- **字体**：已发布的成片是在 Windows 上用「Microsoft YaHei」渲染的。在其他系统上渲染，中文字形会略有不同。要和历史成片完全一致，就在作者的 Windows 电脑上跑这一步。

### 7. 接入图鉴网站（开源 UI 词典）
网站构建时直接读 `EPxx 主题/` 里的动画网页和发布文案，**不用复制**。
- 在 `图鉴网站（开源）/episodes.json` 末尾追加 `{ id, series_no, theme, title, type, keywords }`。`type` 是 2 字类别，例如滚动、悬停、点击、布局、浮层、加载、风格；`keywords` 取发布文案里的核心词和长尾词。
- 先确认 6 个词在 `组件库/components/` 里都有对应组件（没有就先补），再运行 `npm run build`，应输出 `✓ N 期 / 6N 个词条`。生成的 `data/`、`demos/`、`episodes/` 不入库，不要提交。
- 在 `图鉴网站（开源）/README.md` 的「已收录」表格和根目录 `README.md` 的期数表里各加一行。

### 8. 收尾
- 把竖屏成片和封面发给用户看（SendUserFile），并附上推荐的标题。
- 更新 `期数台账.md`：把本期移到“已发布”，写好下一期预告。
- 提交并推送到 GitHub，提交信息格式为 `EPxx：主题（系列第 N 期）`。
- 告诉用户：成片和封面在哪个文件夹，发哪个平台用哪份文案、哪张封面、哪个视频（抖音和小红书用竖屏；B 站、视频号横屏也可以）。

## 只改某一步时
- **只重导视频或封面**：直接跑第 6 步。可以加 `--only portrait` 或 `--only landscape`。
- **只写文案**：第 4、5 步。改完发布文案后重新 `npm run build` 检查。
- **修改已发布的期**：直接改根目录那一期的文件，再 `npm run build`。网站只读这一份，不存在同步问题。
