# 江月 UI

> 说对一个词，AI 就懂你的审美。

「给AI描述UI的6个词」系列的配套词典和组件库，视觉主题是「江上明月」。图鉴网站教你**认识**术语，组件库让你**拿来就用**：

- **几百个术语，20 个主题**（具体数量以网站为准，构建时自动统计）：布局、字体、文字特效、色彩、风格流派、质感、常见组件、表单与输入、数据展示、弹窗浮层、悬停微交互、拖拽与手势、交互状态、动效、响应式、体验，外加 15 个「页面案例」（登录页、仪表盘、定价表、购物车、聊天界面……），演示怎么把多个词组合成一整页；还有 84 个「管理后台」整页参考（6 种页面 × 14 种风格，带中英文提示词）；另有单独的「个人网站」栏目，117 版个人主页、博客、作品集、简历等整页风格
- **每个词都有实时效果**：能点、能动的预览，可以切换桌面 / 平板 / 手机宽度；词典里每张卡片都会自动演示：一只虚拟鼠标替你悬停、点击、拖拽、输入（`assets/autoplay.js`，组件代码不用改，新组件自动生效；只播放屏幕内的卡片，系统开了「减少动态效果」时不播放）
- **随手就能搜**：按 `/` 或 `Ctrl/⌘+K` 打开搜索面板，搜中文、英文、视频期数（如 EP04），或者直接输入“太乱”这种感觉
- **看代码、一键复制**：纯 HTML + CSS + 少量原生 JS，零依赖，贴到任何项目都能跑
- **感觉翻译器**：输入“不高级”“太乱”“点了没反应”，直接给出该用的专业词、效果和提示词
- **提示词篮子**：挑几个词放进篮子，自动拼成一整段提示词，一次发给 AI

## 本地预览

双击 `index.html` 即可。

## 加一个新组件

1. 在 `components/` 下新建 `<英文名>.html`（例如 `bottom-sheet.html`）
2. 文件开头写一段元信息，后面直接写组件代码：

```html
<!--
{
  "en": "Bottom Sheet", "zh": "底部面板",
  "lead": "一句大白话解释它是什么、什么时候用。",
  "prompt": "可以直接复制给 AI 的提示词，带上尺寸、颜色、时长、缓动。",
  "vague": ["可选：用户常说的模糊说法"], "terms": ["可选：相关专业词"], "episode": "可选：对应视频 EPxx"
}
-->
<div class="sheet">…</div>

<style>…</style>

<script>…</script>
```

3. 在 `data/categories.json` 对应主题的 `items` 里登记它的文件名（决定它在哪个主题、排第几）
4. 在仓库根目录运行 `npm run build:ui`，重新生成 `data/components.js`。脚本会检查元信息是否齐全、有没有漏登记或重复登记

“感觉翻译器”的数据在 `data/vague-words.json`，改完同样运行一次 `npm run build:ui`。

## 截图检查

每批新增都要逐张看一遍再上线。`npm run shots` 直接读源文件截图，并拼成两列的总览图放在 `组件库/.shots/`（不入库）：

- `npm run shots -- ui form-wizard bevel`：组件（也可以写主题 id，如 `form`，截整个主题）
- `npm run shots -- web web-east`：调配台词条或整组；`chidu@poster` 可临时换版式试看，`--at=0.5` 看自动滚动到一半的画面
- `npm run shots -- admin dashboard`：管理后台整页（id 包含关键词的都截）；加 `--mobile` 看手机宽度

页面报的 JS 错误会直接打印出来。

## 目录

```
组件库/
  index.html              文档站
  assets/                 文档站的样式和脚本（视觉主题「江上明月」：白天月白、夜里夜江，跟随系统）
  components/*.html       每个组件一个文件（元信息 + 代码）
  data/categories.json    各主题及每个主题包含哪些组件
  data/vague-words.json   感觉翻译器的数据
  data/components.js      由 scripts/build.mjs 生成，不入库、不要手改
  scripts/build.mjs       收录脚本
  admin/                  管理后台整页案例的模板（pages.mjs）和风格（styles.mjs）
  sites/                  「个人网站」栏目的页面模板（pages.mjs）和风格（styles.mjs）
```

## 管理后台整页参考

词典里的「管理后台 · 概览」「管理后台 · 账号」「管理后台 · 系统」三个主题：数据概览、用户列表、账号详情、角色权限、操作日志、系统设置 6 种页面，每种 14 种风格（极简企业、经典深色侧栏、柔和 SaaS、玻璃拟态、新拟物、新粗野、高密度数据、深色科技、复古终端、杂志编辑、瑞士国际、黏土拟态、北欧原木、江月夜色），共 84 个能点能用的整页案例，每个都有中英文提示词。

- 这些案例不是一个个手写的文件，而是「页面模板 × 风格」生成的：`admin/pages.mjs` 放 5 个页面模板和共用外壳，`admin/styles.mjs` 放风格（一组 CSS 变量 + 导航形态 + 少量专属细节）
- **加一种风格**：在 `styles.mjs` 里加一项，每种页面自动各多一个案例；**加一种页面**：在 `pages.mjs` 里照着现有页面写一个，加进 `pages` 数组，并给它填 `cat`（放进哪个主题）
- 在 `data/categories.json` 里写了 `"generated": "admin"` 的主题，`items` 由构建自动填
- 生成的代码自包含（变量、外壳、页面样式、脚本都在一段里），访客复制走就能跑；数据文件里共用的大段代码只存一份，浏览器加载时再拼回去，所以几十个整页也不拖慢网站。为了让页面 HTML 和风格无关、能共用，模板里的颜色一律走 CSS 变量（头像色是 `--av1`～`--av4`），不要把风格里的色值直接写进 HTML
- 一个主题的代码文件接近 400KB 时（构建会提醒），新页面放进新主题（在 `categories.json` 加一个 `"generated": "admin"` 的主题，页面的 `cat` 填它）
- 元信息多了 `canvas`（整页按这个宽度渲染再缩小，卡片和详情页「桌面」看到的是真正的桌面布局）和 `promptEn`（英文提示词，只在详情页用，跟代码一起按需加载）
- 改模板后运行 `npm run build:ui`，再用 `npm run shots -- admin <关键词>` 逐张截图检查（每种风格都要看，深色、玻璃、新拟物、黏土最容易出问题）

## 个人网站栏目

网站顶栏的「个人网站」（`#sites`）：个人主页、博客首页、文章页、作品集、在线简历、链接主页、摄影集、数字花园、周刊订阅页 9 种页面，39 种风格（暖纸极简、纯黑白、瑞士网格、终端极客、新粗野、江月夜色、水墨留白、像素游戏、复古桌面……），每种风格挑 3 种最合适的页面，共 117 版能点能用的整页，每版都有中英文提示词。可以按页面看，也可以「按风格看」（同一风格的 3 种页面拼起来就是一整套个人站）。

- 做法和管理后台一样是「页面模板 × 风格」：`sites/pages.mjs` 放页面和共用骨架，`sites/styles.mjs` 放风格（CSS 变量 + 版式开关 `mods` + 专属细节 `extra` + 适合的页面 `pages`）
- **加一种风格**：在 `styles.mjs` 里加一项，`pages` 挑 3 种页面；`mods` 可选 `navside`（导航改左侧竖栏）、`center`（首屏居中）、`cards`（博客列表做成卡片）；`art` 可选 `k1`～`k6` 指定招牌插画构图
- **加一种页面**：在 `pages.mjs` 里照着现有页面写一个，加进 `pages` 数组；再在 `data/categories.json` 加一个 `"section": "site", "generated": "site"` 的主题，页面的 `cat` 填它
- 页面只认共用类名（`.top .hero .title .card .btn .ph .lk` 等）和 CSS 变量，所以一份 `extra` 对几种页面都生效。插图是纯 CSS 画的抽象画（`.ph.k1`～`.k6`，颜色取 `--a1`～`--a3`），不用任何外部图片和字体；人物、作品、公司、学校全是虚构的，域名用保留的 `.example`
- 截图检查：`npm run shots -- site blog paper`（id 包含任一关键词的都截），`--mobile` 看手机宽度，`--full` 截整页长图
- 风格多了以后：一个页面主题的代码文件超过约 400KB 时，把这种页面拆成两个主题（构建会提醒）；首页索引里每版只放名字和提示词，代码按需加载

## 提示词调配台（试做）

`prompts.html`（线上是 `/ui/prompts.html`）：视频运镜与景别、图片光线与构图、网站风格。每个词一张卡片，带会动的原创预览、中英提示词、「容易用错的地方」和反面提示词，勾几个就拼成一整段提示词。

- 词条在 `prompts/<英文名>.html`，格式和 `components/` 一样（开头 JSON 元信息 + 预览代码），多了 `promptEn`（英文提示词）、`avoid`（容易用错的地方）、可选的 `neg`（["中文反面词", "English"]）
- 预览只用 HTML + CSS，直接画进卡片、不开 iframe，屏幕外自动暂停，所以再多也不卡
- 几个组可以共用一个「只能选一个」：在分组上写 `"exclusive": "同一个名字"`（几十种网站风格分好几组，但整站只能选一种）
- 同一组词共用一个「舞台」`prompts/_<名字>.html`：运镜和景别共用分层的晴天草地（词条只写几行摄影机关键帧），光线共用半身像，网站风格共用一个虚构书房官网（词条只写 CSS）
- 很多词条重复的 CSS 抽成「骨架」`prompts/_<名字>.css`，词条元信息写 `"kit": "<名字>"` 就会先套上它（网站风格都用 `_site-kit.css`，词条只写自己的配色和差异）。网站风格要分批加，每批先过审美规则、逐张截图检查再上线
- **版式骨架**：网站风格不该都长一个样，所以除了换配色，还能换排法。`prompts/_layout-<名字>.css` 是 7 种版式（居中 centered、竖排 vertical、杂志 magazine、分屏 split、海报 poster、便当格 bento、侧栏 sidebar），用同一个书房页面的同一份 HTML、只用 CSS 重新排。词条元信息写 `"layout": "<名字>"` 就套上，构建时会把 `data/prompt-layouts.json` 里这种版式的中英文说明自动拼到提示词末尾，卡片左下角也会标出版式名。新风格挑一个最贴合的版式；早期的风格没写 layout，用默认的「左文右图」，以后按分组逐步迁移（迁移时要重新截图，因为旧词条的 CSS 是照默认版式写的）
- **筛选标签**：顶部栏第二行是「感觉」标签（复古、东方、温暖……可多选，要同时符合）和「版式」标签（单选），和搜索框一起生效。感觉标签在 `data/prompt-tags.json` 里定义：每个标签一组关键词，构建时匹配词条的名字、别名和一句话简介自动打上；匹配不到但确实属于的，在词条元信息里写 `"tags": ["retro"]` 手动补。少于 5 个词条的标签不显示
- 页面带搜索框（分组名、中英文名、别名、简介都能搜）和分组跳转，词条到几百个也好找
- 在 `data/prompt-groups.json` 登记分组，运行 `npm run build:ui` 生成 `data/prompts.js`（文字索引，一打开就加载）和 `data/prompt-code/<分组>.js`（预览代码，卡片快到屏幕时才按分组加载），做法和组件库的 `data/code/` 一样
- 构建输出会打印索引大小和最大分组的代码大小；单个分组代码超过约 300KB 时，把它拆成两个分组
- 收录规则见调研文档：不收堆砌词、不点名在世艺术家和品牌、不收 AI 味模板，每个词都要写「容易用错的地方」

## 文档站的设计取舍

来这里的人大多不是设计师：一类是想让 AI 改界面、却说不出专业词的人，一类是刷到抖音视频、点进来找同款的观众（多数用手机）。所以：

- **首屏就是感觉翻译器**：一进来就能说“不高级”“太乱”，直接拿到专业词和一句能发给 AI 的话，不用先学分类
- **提示词比代码重要**：词条页右侧（手机上是底部常驻按钮）最显眼的是「复制这句话」，代码放在第二位
- **配色克制**：默认跟随系统明暗。白天用暖白「月白」底，组件预览本身就是浅色，不会一块白一块黑；江月橘只用在主按钮、当前位置和篮子数量上
- **手机优先**：底部标签栏（翻译 / 词典 / 搜索 / 篮子），主题筛选横向滑动，篮子从底部弹出

## 发布

合并到 `main` 后，GitHub Actions 会自动把图鉴网站发布到 Pages 根目录，组件库发布到 `/ui/`。

## 规模变大以后（已经做好的准备）

组件到几百、上千个也不会卡，靠的是三件事：

- **数据拆开**：`data/components.js` 只放名字、说明和提示词（搜索、感觉翻译、篮子只用这些），一打开就加载；组件代码按主题分成 `data/code/<主题>.js`，滚到这个主题、或打开它的词条时才加载
- **卡片按需生成**：「词典 · 全部」先给每个主题留出等高的空位，快滚到时才生成卡片
- **预览不常驻**：卡片平时只显示静态首帧；屏幕里看得见的全部一起播放、一直循环；滑出屏幕就把 iframe 整个删掉，所以同时在跑的只有一屏的量

一个主题的代码超过 400KB 时，构建脚本会提醒，把它拆成两个主题就行。
