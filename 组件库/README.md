# 江月 UI

> 说对一个词，AI 就懂你的审美。

「给AI描述UI的6个词」系列的配套词典和组件库，视觉主题是「江上明月」。图鉴网站教你**认识**术语，组件库让你**拿来就用**：

- **184 个术语，17 个主题**：布局、字体、文字特效、色彩、风格流派、质感、常见组件、表单与输入、数据展示、弹窗浮层、悬停微交互、拖拽与手势、交互状态、动效、响应式、体验，外加 15 个「页面案例」（登录页、仪表盘、定价表、购物车、聊天界面……），演示怎么把多个词组合成一整页
- **每个词都有实时效果**：能点、能动的预览，可以切换桌面 / 平板 / 手机宽度；词典里每张卡片都会自动演示：一只虚拟鼠标替你悬停、点击、拖拽、输入（`assets/autoplay.js`，组件代码不用改，新组件自动生效；只播放屏幕内的卡片，系统开了「减少动态效果」时不播放）
- **随手就能搜**：按 `/` 或 `Ctrl/⌘+K` 打开搜索面板，搜中文、英文、视频期数（如 EP04），或者直接输入“太乱”这种感觉
- **看代码、一键复制**：纯 HTML + CSS + 少量原生 JS，零依赖，贴到任何项目都能跑
- **感觉翻译器**：输入“不高级”“太乱”“点了没反应”，直接给出该用的专业词、效果和提示词
- **提示词篮子**：挑几个词放进篮子，自动拼成一整段提示词，一次发给 AI

## 本地预览

双击 `index.html` 即可。

## 加一个新组件

1. 在 `components/` 下新建 `<英文名>.html`（例如 `bottom-sheet.html`）
2. 文件开头写一段元信息，后面直接写组件代码：

```html
<!--
{
  "en": "Bottom Sheet", "zh": "底部面板",
  "lead": "一句大白话解释它是什么、什么时候用。",
  "prompt": "可以直接复制给 AI 的提示词，带上尺寸、颜色、时长、缓动。",
  "vague": ["可选：用户常说的模糊说法"], "terms": ["可选：相关专业词"], "episode": "可选：对应视频 EPxx"
}
-->
<div class="sheet">…</div>

<style>…</style>

<script>…</script>
```

3. 在 `data/categories.json` 对应主题的 `items` 里登记它的文件名（决定它在哪个主题、排第几）
4. 在仓库根目录运行 `npm run build:ui`，重新生成 `data/components.js`。脚本会检查元信息是否齐全、有没有漏登记或重复登记

“感觉翻译器”的数据在 `data/vague-words.json`，改完同样运行一次 `npm run build:ui`。

## 目录

```
组件库/
  index.html              文档站
  assets/                 文档站的样式和脚本（视觉主题「江上明月」：白天月白、夜里夜江，跟随系统）
  components/*.html       每个组件一个文件（元信息 + 代码）
  data/categories.json    各主题及每个主题包含哪些组件
  data/vague-words.json   感觉翻译器的数据
  data/components.js      由 scripts/build.mjs 生成，不入库、不要手改
  scripts/build.mjs       收录脚本
```

## 提示词调配台（试做）

`prompts.html`（线上是 `/ui/prompts.html`）：视频运镜与景别、图片光线与构图、网站风格。每个词一张卡片，带会动的原创预览、中英提示词、「容易用错的地方」和反面提示词，勾几个就拼成一整段提示词。

- 词条在 `prompts/<英文名>.html`，格式和 `components/` 一样（开头 JSON 元信息 + 预览代码），多了 `promptEn`（英文提示词）、`avoid`（容易用错的地方）、可选的 `neg`（["中文反面词", "English"]）
- 预览只用 HTML + CSS，直接画进卡片、不开 iframe，屏幕外自动暂停，所以再多也不卡
- 同一组词共用一个「舞台」`prompts/_<名字>.html`：运镜和景别共用分层的江边夜景（词条只写几行摄影机关键帧），光线共用半身像，网站风格共用一个虚构书房官网（词条只写 CSS）
- 在 `data/prompt-groups.json` 登记分组，运行 `npm run build:ui` 生成 `data/prompts.js`
- 收录规则见调研文档：不收堆砌词、不点名在世艺术家和品牌、不收 AI 味模板，每个词都要写「容易用错的地方」

## 文档站的设计取舍

来这里的人大多不是设计师：一类是想让 AI 改界面、却说不出专业词的人，一类是刷到抖音视频、点进来找同款的观众（多数用手机）。所以：

- **首屏就是感觉翻译器**：一进来就能说“不高级”“太乱”，直接拿到专业词和一句能发给 AI 的话，不用先学分类
- **提示词比代码重要**：词条页右侧（手机上是底部常驻按钮）最显眼的是「复制这句话」，代码放在第二位
- **配色克制**：默认跟随系统明暗。白天用暖白「月白」底，组件预览本身就是浅色，不会一块白一块黑；江月橘只用在主按钮、当前位置和篮子数量上
- **手机优先**：底部标签栏（翻译 / 词典 / 搜索 / 篮子），主题筛选横向滑动，篮子从底部弹出

## 发布

合并到 `main` 后，GitHub Actions 会自动把图鉴网站发布到 Pages 根目录，组件库发布到 `/ui/`。

## 规模变大以后

现在所有组件打包进一个 `data/components.js`（184 个组件约 370KB），卡片预览只在滚动到可见时才加载，打开就能用，不需要服务器。等组件到三四百个、这个文件超过 1MB 时，可以改成每个组件单独生成一个文件、按需加载，文档站外壳不用动。
